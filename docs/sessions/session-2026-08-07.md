## 09:10 작업 (주문 상태 변경 알림이 다른 계정 기기로 새는 문제 조사·수정)

**요청:** "주문을 진행한 팀장의 기기에 슈퍼관리자가 해당 주문건을 보고 상태를 변경했다면 변경된 상태를 알려주는 알림이 갈 수 있게 해줘." → 조사 결과 이미 구현되어 있었으나(트리거 `trg_notify_order_status` → Edge Function `order-notify` → 웹푸시), 실제로는 상태 변경 대상 팀장(아크)이 아니라 슈퍼관리자 테스트 계정이 로그인된 기기로 알림이 도착하는 버그를 사용자가 재현.

**작업 내용:**
- Supabase 원격 조사: `push_subscriptions` 테이블에서 "테스트 슈퍼관리자"(super_admin)와 "아크"(sales_rep) 두 프로필이 동일한 FCM endpoint로 각각 구독 행을 갖고 있음을 확인 — 같은 테스트 기기에서 계정을 바꿔가며 로그인 후 "알림 켜기"를 눌러 이전 계정 구독이 해제되지 않고 새 계정 구독이 추가된 것이 원인. `order-notify` 함수 자체의 수신자 지정 로직(`order.sales_rep_id`만 대상)은 정상이었음.
- 꼬여있던 테스트 구독 데이터 정리: 슈퍼관리자 테스트 계정에 남아있던 중복 구독 행 삭제.
- 재발 방지: `src/context/AuthContext.tsx`의 `signOut()`에서 `supabase.auth.signOut()` 호출 전 `unsubscribeFromPush(profile.id)`를 호출하도록 수정 — 로그아웃 시 현재 기기의 푸시 구독을 자동 해제해, 같은 기기에서 다른 계정으로 로그인해도 이전 계정 알림이 새 계정 기기로 섞이지 않게 함.

**결과:** 완료. `tsc --noEmit` 통과. Supabase에서 슈퍼관리자 테스트 계정에 남아있던 중복 구독 행(아크 팀장과 동일 endpoint) 삭제 확인. `AuthContext.signOut()`이 로그아웃 시 `unsubscribeFromPush(profile.id)`를 호출하도록 수정 — 실제 기기의 브라우저 알림 권한/서비스워커 구독 해제는 Playwright 헤드리스로는 검증이 어려워, 코드 리뷰 및 타입체크로 확인. UI 변경이 없는 로직 수정이라 스크린샷은 생략.

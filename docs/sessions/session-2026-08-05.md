## 20:15 작업 (PWA 업데이트 알림 배너 추가)
**요청:** "홈 화면으로 추가하기를 통해 각 기기별로 설치한 앱에서 코드가 수정되어 새로고침해야 할 때 앱을 종료한 후 다시 실행해야 적용되고 있거든? 이건 어쩔 수 없는거지? 만약 그렇다면 코드가 수정되어 다시 배포되었을 때 알림이나 메시지창으로 앱을 종료하고 다시 실행하라고 알려줄 수 있을까?"
**작업 내용:**
- 원인: (1) `src/sw.ts`에 skipWaiting 처리가 없어 새 서비스워커가 계속 waiting 상태로만 남아있었음 (2) `vite.config.ts`의 `registerType: 'autoUpdate'`는 vite-plugin-pwa 내부적으로 배너/버튼 없이 조용히 새로고침하거나 아무 동작도 하지 않는 코드 경로를 타서, 배너+수동클릭 방식과 근본적으로 호환되지 않음(내부 번들 코드 직접 확인)
- `vite.config.ts`: `registerType`을 `'autoUpdate' → 'prompt'`로 변경
- `src/sw.ts`: `message` 이벤트로 `SKIP_WAITING` 수신 시 `self.skipWaiting()` 호출 추가, `clientsClaim()` 추가
- `src/components/UpdatePrompt.tsx`(신규): `virtual:pwa-register/react`의 `useRegisterSW()`로 새 버전 감지 시 화면 하단에 "새 버전이 있습니다" 배너 표시, "업데이트" 클릭 시 skipWaiting 메시지 전송 + `controllerchange` 이벤트를 직접 감지해 리로드(라이브러리 내장 리로드가 Workbox의 `isUpdate` 판정에 의존해 일부 상황에서 누락되는 것을 확인해 직접 리스너로 보강)
- `src/vite-env.d.ts`: `vite-plugin-pwa/react` 타입 참조 추가
- `src/App.tsx`: `UpdatePrompt` 컴포넌트 마운트
- 30분 주기로 서비스워커 업데이트 자동 확인(`registration.update()`) 추가
**결과:** 완료. `npx tsc -b` 클린 통과. `vite preview`+Playwright로 실제 배포 시나리오 전체 사이클 검증: 새 빌드 배포 → 서비스워커가 waiting 상태 진입 감지 → "새 버전이 있습니다" 배너 노출 → "업데이트" 클릭 → 실제 페이지 리로드(`performance` 네비게이션 엔트리로 확인) → 새 서비스워커 active/controlling 전환 → 배너 자동 소멸까지 정상 동작 확인. 스크린샷: `20260805-203038-before-update-banner.png`, `20260805-203038-after-update-banner.png`. 변경 파일: `vite.config.ts`, `src/sw.ts`, `src/components/UpdatePrompt.tsx`(신규), `src/vite-env.d.ts`, `src/App.tsx`. git 커밋/푸시는 아직 요청받지 않아 보류.

## 00:15 작업 (Vercel 배포 — vercel.json 추가 + 빌드 에러 수정)
**요청:** "vercel.json 추가해줘. 그리고 vercel에 올릴 때 루트 디렉토리는 그냥 './' 이걸로 하면 될까?" → 이어서 Vercel 실제 배포 시도 중 빌드 실패 로그 공유("src/routes/OrderNew.tsx(293,7): error TS6133 'productTypeLabel' is declared but its value is never read." 등 2건) → "수정 추가된 코드 깃허브에 올려줘"
**작업 내용:**
- 저장소 루트(`app/`)가 곧 `package.json` 위치임을 `git rev-parse --show-toplevel`로 재확인 — Vercel Root Directory는 `./`로 안내
- `vercel.json` 신규 추가 — `BrowserRouter` 사용 중이라 SPA 하위 경로 새로고침 시 404 방지용 rewrite(`"/(.*)" → "/index.html"`)
- Vercel 빌드 실패(`tsc -b` 에러 2건) 원인 파악: `src/routes/OrderNew.tsx`에 사용되지 않는 `productTypeLabel` 상수, `navigate`(`useNavigate` 결과), `ProductType` import가 이전 리팩터링 후 정리되지 않고 남아있었음 — 로컬에서 그동안 검증에 썼던 `npx tsc --noEmit`(단일 파일 모드)는 unused-symbol 에러를 잡지 못했고, Vercel이 실행하는 `npm run build`(`tsc -b`, 프로젝트 참조 모드)에서만 걸러짐. 셋 다 삭제
**결과:** 완료. `npx tsc -b` 클린 통과 확인 후, `rm -rf dist && npm run build`로 Vercel과 동일한 커맨드를 로컬 재현해 정상 빌드(`dist/` 산출물 생성, PWA service worker 포함) 확인. **향후 검증 시 `tsc --noEmit` 대신 `tsc -b`(또는 `npm run build`)를 기준으로 삼을 것** — 이번 빌드 실패의 직접 원인.
